# 实现边界与延伸阅读

[English](../en/tutorial/implementation-notes.md)

## 如何理解这套实现

本系列从对象创建开始，在具体需求出现时逐步拆分职责：Bean 定义与实例分开，请求映射与调用分开，JDBC 固定流程与行映射分开，增强行为与方法匹配分开。

每篇文章包含完整程序、运行命令、预期输出和练习。先验证当前阶段的行为，再通过失败场景检查边界。第 17 篇把容器、MVC、代理和数据库连接起来，验证成功更新与失败回滚。

## 关键约定

| 主题 | 本系列的约定 | 继续扩展时需要考虑 |
| --- | --- | --- |
| 单例 | 单例身份属于当前容器内的 Bean 定义 | 同一个类可以对应多个定义或多个容器，不能据此推断 JVM 内只有一个实例 |
| 线程安全 | 容器按单线程启动，启动后不修改定义 | 并发 Map 不自动保证创建原子性、安全发布或业务对象的线程安全 |
| 循环依赖 | 主容器拒绝循环依赖，第 04 篇单独演示 Setter 环 | 构造器环、代理身份和创建失败后的缓存清理需要分别处理 |
| 注解注入 | 默认按唯一类型匹配，可用显式名称选择 | 多候选解析和完整注解语义需要更细致的规则 |
| Web 入口 | 第 17 篇使用 JDK HttpServer | Servlet 集成、请求体解析和通用 JSON 处理不在当前实现范围内 |
| 自动代理 | 传递处理器的返回值，缓存并注入最终代理 | 早期引用与最终代理必须保持一致，不能只判断是否打印了增强日志 |
| AOP | 使用 JDK 接口代理和拦截链 | 自调用不会经过代理；类代理和字节码织入需要其他实现机制 |
| JDBC | 模板管理固定流程，行映射由调用者提供 | 连接池、多数据源和读写路由需要明确资源归属与并发规则 |
| 事务 | 当前线程绑定连接，正常提交、异常回滚并清理，拒绝嵌套 | 传播行为、跨线程调用与多资源协调需要独立设计 |

## 验证与练习

不要只检查“可以运行”。还应验证实例身份、初始化顺序、异常是否保留、资源是否关闭，以及数据库中的实际值。各章断言和综合篇请求示例给出了可重复执行的检查步骤。

中英文版使用一致的可执行代码和预期输出，注释与讲解分别采用对应语言。代码验证方式见[验证记录](验证记录.md)。
