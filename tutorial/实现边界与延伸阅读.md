# 实现边界与扩展方向

[English](../en/tutorial/implementation-notes.md) · [系列目录](../README.md)

本系列的设计单位是一次预约的业务约束。提取容器、代理或模板时，不能改变库存与预约记录的守恒关系。

| 领域 | 当前约定 | 扩展前必须回答的问题 |
| --- | --- | --- |
| 业务 | 一本样例书；预约编号唯一，同书同读者唯一 | 取消、过期和重复取消怎样影响库存？ |
| 并发 | 内存版本使用对象锁；数据库版本使用条件更新 | 换数据库后的隔离和锁等待行为是否仍满足断言？ |
| 持久化 | 文件型 H2 保留数据，启动不重置已有书 | 多个实例同时初始化、迁移与恢复由谁协调？ |
| 事务 | 一线程一层，成功提交、失败回滚，拒绝嵌套 | 传播、跨线程调用和提交结果不明确时采用什么协议？ |
| JDBC | 模板借用事务连接，负责语句和结果集 | 若接入连接池，谁负责重置状态和淘汰坏连接？ |
| 代理 | JDK 接口代理，reserve 方法匹配事务 | 新写方法如何加入规则，自调用是否绕过代理？ |
| 容器 | 单线程配置、构造器注入、单例、拒绝环 | 基本类型、多个候选构造器和新作用域如何选择？ |
| 生命周期 | 构造对象由容器拥有，传入对象由调用者拥有 | 构造中途失败如何清理，关闭失败如何保留证据？ |
| 配置 | 可信本地 XML，严格的 bean/ref 语言 | 配置校验失败后的原子恢复和热重载是否需要实现？ |
| Web | 单值 Query，String/long 参数，UTF-8 文本 | JSON、认证、限流、取消与幂等重放如何定义？ |

## 并发与身份是不同的问题

容器的单例身份只说明多个入口拿到同一个完成对象，不表示对象内部业务状态自动线程安全。本项目在启动后冻结对象图与路由表，请求期间的数据库连接由 ThreadLocal 分隔，库存由数据库更新条件约束。

一个代理存在，也不能保证所有调用经过它。直接调用原始服务或仓储、在目标内部通过 this 调用写方法，都可能绕过事务。验收既检查边界，又查询最终数据。

## 下一项业务扩展

可以研究预约取消：先定义哪些状态允许取消、重复取消如何响应，再增加取消记录与库存恢复的同一事务。之后才考虑过期回收。不要直接让后台任务无条件加库存，否则重试可能重复归还。

进一步理解机制时，可阅读 [JDK 17 API](https://docs.oracle.com/en/java/javase/17/docs/api/) 与 [Spring Framework 官方文档](https://docs.spring.io/spring-framework/reference/)。这些文档不是运行示例的前置条件，本项目也不承诺兼容完整 Spring API。
