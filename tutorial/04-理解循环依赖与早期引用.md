# 第四篇 理解循环依赖与早期引用

[English](../en/tutorial/04-circular-dependencies.md)

A 依赖 B，B 又依赖 A 时，第三篇的容器会报告循环。本篇建立一个独立的小实验，展示无参构造之后再填充引用时，怎样使用早期对象完成装配。

这不是给所有循环依赖打开开关。当前代码只研究单线程、无代理的 Setter 型引用环；构造器必须先产生对象，才有早期引用可供别人使用。不要把它直接并入后面的代理容器。

ready 保存完成对象，early 保存已构造但未填充完的对象，creating 用于检测还没有早期引用可用的创建环。

## 完整代码

将下面整段保存为 `Demo04.java`。所需类、接口、注解、工具方法和入口均在代码中，无需其他教程源码。

```java
import java.util.HashMap;
import java.util.HashSet;
import java.util.Map;
import java.util.Objects;
import java.util.Set;
import java.util.function.BiConsumer;
import java.util.function.Supplier;

/** 只演示无代理的 Setter 循环，早期引用不能解决构造器循环。 */
public class Demo04 {
  record Definition(Supplier<Object> constructor, BiConsumer<Object, Factory> populate) {}

  static class Factory {
    final Map<String, Definition> definitions = new HashMap<>();
    final Map<String, Object> ready = new HashMap<>();
    final Map<String, Object> early = new HashMap<>();
    final Set<String> creating = new HashSet<>();
    boolean failed;

    Object get(String name) {
      if (failed) throw new IllegalStateException("discard failed factory");
      if (ready.containsKey(name)) return ready.get(name);
      if (early.containsKey(name)) return early.get(name);
      Definition d = Objects.requireNonNull(definitions.get(name), "missing " + name);
      // 重复进入同一创建路径说明存在依赖环，本容器选择立即拒绝。
      if (!creating.add(name)) throw new IllegalStateException("constructor cycle: " + name);
      try {
        Object bean = d.constructor().get();
        // 先暴露已构造但未填充属性的对象，才能打断 Setter 相互依赖。
        early.put(name, bean);
        d.populate().accept(bean, this);
        // 属性填充成功后升级为完成对象，早期引用随后在 finally 中移除。
        ready.put(name, bean);
        return bean;
      } catch (RuntimeException | Error e) {
        // 其他已完成对象可能持有这个半成品，因此失败时整个工厂都必须废弃。
        failed = true;
        ready.clear();
        early.clear();
        throw e;
      } finally {
        early.remove(name);
        creating.remove(name);
      }
    }
  }

  static class A {
    B b;
  }

  static class B {
    A a;
  }

  public static void main(String[] args) {
    var f = new Factory();
    f.definitions.put("a", new Definition(A::new, (bean, ctx) -> ((A) bean).b = (B) ctx.get("b")));
    f.definitions.put("b", new Definition(B::new, (bean, ctx) -> ((B) bean).a = (A) ctx.get("a")));
    A a = (A) f.get("a");
    check(a.b.a == a && f.early.isEmpty(), "early identity and cleanup");
    var broken = new Factory();
    broken.definitions.put(
        "a",
        new Definition(
            A::new,
            (bean, ctx) -> {
              ctx.get("b");
              throw new IllegalStateException("init");
            }));
    broken.definitions.put(
        "b", new Definition(B::new, (bean, ctx) -> ((B) bean).a = (A) ctx.get("a")));
    try {
      broken.get("a");
      throw new AssertionError("failure hidden");
    } catch (IllegalStateException expected) {
      check(broken.ready.isEmpty() && broken.early.isEmpty(), "discard all polluted objects");
    }
    System.out.println("PASS cycle: setter identity, early cleanup, failed factory discarded");
  }

  static void check(boolean condition, String message) {
    if (!condition) throw new AssertionError(message);
  }
}
```

## 编译与运行

使用 JDK 17，在保存文件的目录执行：

```bash
javac --release 17 Demo04.java
java Demo04
```

预期输出：

```text
PASS cycle: setter identity, early cleanup, failed factory discarded
```

## 逐步跟踪 A 与 B

先创建 A 并放进 early，再填充 A.b。获取 B 时同样先构造 B，随后填充 B.a；此时 get("a") 可以命中早期 A。B 完成后回到 A 的填充，最后 A 也完成。

代码断言 `a.b.a == a`。这个身份条件比“没有无限递归”更重要：如果创建了第二个 A，程序虽然也可能结束，单例关系却已经错误。

若把依赖放到构造器执行之前，early 里尚无对象，creating 会识别环。多加一层缓存不能创造一个还没完成构造的实例。

## 为什么失败时清空整个工厂

第二个测试让 A 填充时抛错，此前 B 已经拿到早期 A。只删 A 会留下持有坏引用的 B，所以实验清空两个缓存，并将工厂标记为 failed，之后禁止继续使用。

细粒度恢复需要依赖图和撤销机制，不是删一个 Map 条目就能完成。早期引用也只解决装配，不保证初始化途中调用任意业务方法是安全的。

## 与代理组合时的边界

若 B 提前拿到原始 A，之后容器却对外返回 A 的代理，B 的调用就可能绕过增强。完整协作需要一致的早期代理协议；本系列的主容器仍拒绝环。

练习：让构造 A 的 Supplier 先执行 get("b")，再让构造 B 的 Supplier 执行 get("a")，观察为什么报 constructor cycle。然后恢复代码，保留本篇的两个身份和失败清理断言。
