# 第十三篇 用动态代理增强业务方法

[English](../en/tutorial/13-dynamic-proxies.md)

业务方法开始前要审计、结束后要计时，如果每个方法都手写，重复流程就会散落在 Service 中。本篇让调用先经过一个代理，再由代理调用真正的对象。

JDK 动态代理实现业务接口，InvocationHandler 负责方法调用。它不修改目标对象，也不是目标实现类的子类，所以调用者依赖 Users 接口。

下面把业务接口、实现类、代理工厂和测试全部写出，特别检查自调用与业务异常两个容易误解的行为。

## 完整代码

将下面整段保存为 `Demo13.java`。所需类、接口、注解、工具方法和入口均在代码中，无需其他教程源码。

```java
import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Proxy;
import java.util.ArrayList;
import java.util.List;

/** 用 JDK 接口代理演示环绕增强，以及目标对象自调用绕过代理的边界。 */
public class Demo13 {
  public interface Users {
    String find(long id);

    String outer(long id);

    void fail();
  }

  public static class UserService implements Users {
    public String find(long id) {
      return "user-" + id;
    }

    // 这里是目标对象内部的直接调用，不经过代理，因此不会触发 find 的增强。
    public String outer(long id) {
      return find(id);
    }

    public void fail() {
      throw new IllegalArgumentException("business failure");
    }
  }

  public static Users proxy(Users target, List<String> trace) {
    return (Users)
        Proxy.newProxyInstance(
            Users.class.getClassLoader(),
            new Class<?>[] {Users.class},
            (proxy, method, args) -> {
              // equals 和 hashCode 使用代理自身的身份语义，避免转发后破坏自反性。
              if (method.getDeclaringClass() == Object.class) {
                return switch (method.getName()) {
                  case "equals" -> proxy == args[0];
                  case "hashCode" -> System.identityHashCode(proxy);
                  case "toString" -> "UsersProxy";
                  default -> throw new UnsupportedOperationException(method.getName());
                };
              }
              boolean enhanced = method.getName().equals("find");
              if (enhanced) trace.add("before");
              try {
                return method.invoke(target, args);
              } catch (InvocationTargetException e) {
                // 解开反射包装，让调用者和事务增强看到原始业务异常。
                throw e.getCause();
              } finally {
                if (enhanced) trace.add("after");
              }
            });
  }

  public static void main(String[] args) {
    List<String> trace = new ArrayList<>();
    Users users = proxy(new UserService(), trace);
    String result = users.find(7);
    check(result.equals("user-7") && trace.equals(List.of("before", "after")), "proxy invocation");
    System.out.println(result);
    System.out.println(trace);
    trace.clear();
    check(users.outer(7).equals("user-7"), "self invocation result");
    check(trace.isEmpty(), "self invocation must bypass find advice");
    System.out.println("self invocation bypassed advice");
    try {
      users.fail();
      throw new AssertionError("exception hidden");
    } catch (IllegalArgumentException e) {
      check(e.getMessage().equals("business failure"), "original cause");
      System.out.println(e.getMessage());
    }
    check(users.equals(users), "proxy identity equality");
  }

  static void check(boolean condition, String message) {
    if (!condition) throw new AssertionError(message);
  }
}
```

## 编译与运行

使用 JDK 17，在保存文件的目录执行：

```bash
javac --release 17 Demo13.java
java Demo13
```

预期输出：

```text
user-7
[before, after]
self invocation bypassed advice
business failure
```

## 一次调用到底经过谁

外部调用 users.find，进入代理的 invoke，再执行目标对象的 find。before 与 finally 中的 after 围绕目标调用发生，而返回值保持不变。

反射会把业务异常包装成 InvocationTargetException。代理取出 cause 重新抛出，使调用者仍能按业务异常类型处理错误。本例使用运行时异常；接口之外的受检异常还受到 JDK 代理异常契约约束。

## 为什么 outer 内部的 find 没有增强

代理把 outer 委托给目标对象，目标内部的 find 等价于 this.find，没有重新进入外部代理。代码检查 trace 为空，说明“代理对象存在”不意味着目标内部每次调用都经过增强。

Object 方法也定义了语义：equals 使用代理引用身份，hashCode 与其一致，toString 返回说明文字。不能把它们毫无区分地转给目标对象，否则可能出现代理连自身都不相等的行为。

## 动手修改

把匹配条件改成所有业务方法，观察 outer 入口会被增强，但内部 find 仍不会额外经过代理。再让 find 抛异常，finally 中的 after 仍会执行；如果想要“只在成功时执行”，就应把逻辑写在 invoke 正常返回之后。
