# 一步步手写 Spring：从图书预约出发

[English](en/README.md) · [在线阅读](https://codeideaai.github.io/spring-from-scratch/zh.html) · [GitHub](https://github.com/codeideaai/spring-from-scratch)

一本书不能被两个人同时抢走；预约失败，库存必须恢复。我们从这些业务约束出发，逐步写出事务、代理、容器和路由，而不是先搭一套框架再寻找用途。

前四篇让内存预约与接口契约成立，第五篇主动制造数据库的部分提交，随后引入事务和模板。等到多个入口开始重复装配，再实现工厂、构造器依赖图、生命周期与自动代理。最后用真实 HTTP 和并发请求验收整个系统。

## 完整示例项目

[图书预约项目](examples/library/README.zh.md)使用常规 Java 包和组件文件，提供命令行启动、文件型数据库与自动验收。文章的独立 Demo 与项目的分文件结构服务于不同阅读方式；所有框架实现都在本仓库中。

```bash
mkdir -p build/lib
curl -fL -o build/lib/h2-2.2.224.jar https://repo.maven.apache.org/maven2/com/h2database/h2/2.2.224/h2-2.2.224.jar
bash examples/library/run.sh test
bash examples/library/run.sh serve
```

## 验证与边界

核心检查包括数量守恒、重复预约回滚、竞争最后一本、连接归属、启动失败清理和实际 HTTP 状态。[验证记录](tutorial/验证记录.md)说明检查覆盖；[实现边界](tutorial/实现边界与延伸阅读.md)说明哪些能力尚未实现。

这是用于理解框架控制流程的教学系统，没有认证、取消、过期、分布式事务或完整 Spring API 兼容性。
